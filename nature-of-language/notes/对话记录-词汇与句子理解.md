## 1. Iteration /ˌɪtəˈreɪʃən/

### 词源拆解
- **iter-**（拉丁语 iterare = to do again，再做一次）
- **-ation**（名词后缀 = the act/process of，表示"……的过程/行为"）

### 核心含义
重复做某事的过程；一次迭代循环

### 常见语境

| 场景 | 含义 | 例句 |
|------|------|------|
| 软件开发 | 迭代（一个开发周期） | We plan 2-week iterations. |
| 数学/编程 | 循环的一次执行 | Each iteration updates the value. |
| 一般用法 | 版本/改良版 | The latest iteration of the product. |

## 2. Bootstrap

### 词源
来自短语 **"pull oneself up by one's bootstraps"**（拽着自己靴子上的带子把自己提起来）——一个不可能的动作，隐喻**靠自身力量从零开始启动**。

### 形象画面
想象一个人坐在地上，拽着自己靴子上的带子想把自己提起来——这当然不可能，但这个画面传达的就是：**没有任何外力帮忙，完全靠自己从零站起来**。

### 核心语义
从无到有、自我启动的过程

### 不同语境下的含义

| 语境 | 含义 | 关键特征 |
|------|------|----------|
| **计算机/软件** | 启动、初始化 | 系统从零加载自身 |
| 前端框架 (Bootstrap) | CSS框架名 | 帮你"快速启动"UI开发 |
| 创业 | 自力更生创业 | 不靠外部融资，自己启动 |
| 统计学 | 自助法（重采样） | 用已有数据"自我生成"更多样本 |

### 例句
> "tries to bootstrap a Python plugin" = 尝试**启动/初始化**一个 Python 插件

bootstrap ≈ initialize + start up，但强调的是**从零到可用的整个自启动过程**。

## 3. tlinux / distro / repos

### 原句
> tlinux 2.4 is a CentOS 7-based distro with limited repos.

### 逐词解析

| 词 | 含义 |
|----|------|
| **tlinux** | Tencent Linux 的缩写——腾讯内部定制的 Linux 操作系统 |
| **distro** | distribution 的口语缩写 = 发行版 |
| **limited repos** | repos = repositories（软件仓库）的缩写；limited repos = 可用的软件源有限 |

### 翻译
tlinux 2.4 是一个基于 CentOS 7 的 Linux 发行版，可用的软件仓库比较有限。

## 4. Selector

### 词源拆解
- **select**（动词）= 选择、挑选（来自拉丁语 *seligere*: se- 分开 + legere 挑选）
- **-or**（后缀）= 做这个动作的东西/工具

### 核心直觉
**面对一堆东西 → 用某种规则/条件 → 精准挑出你要的那个（或那些）**

```
一堆东西        selector（规则）        挑出的结果
─────────  ──→  ─────────────  ──→  ──────────
所有 DOM 节点    .btn               所有 class="btn" 的元素
整个 Redux state  selectUser        state.user 这部分数据
一排开关         频道选择器          第 3 频道
```

### 不同语境

| 语境 | 含义 | 它"选"什么？ |
|------|------|-------------|
| **CSS** | 选择器 | 选中页面上的 HTML 元素 |
| **Redux/状态管理** | 选择器函数 | 从 state 树中挑选出需要的数据 |
| **测试 (Playwright等)** | 定位器/选择器 | 选中页面上要操作的元素 |
| **硬件** | 选择开关 | 在多个选项中切换选一个 |

## 5. Entry

### 原句
> Duplicate entry '1793-system_architect'

### 核心语义
**Entry** 来自 **enter**（进入/录入），**-ry** 是名词后缀 = **被录入/登记进去的一条东西**

数据库里每 insert 一行，就是添加一个 entry。报错就是说这个 entry 已经 enter 过了，不能再 enter 一次。

### 不同语境

| 语境 | 含义 | 例子 |
|------|------|------|
| **数据库** | 一条记录（一行数据） | Duplicate entry = 重复记录 |
| **字典** | 一个词条 | The dictionary has 50,000 entries |
| **日记/账本** | 一条记录 | a journal entry = 一条日记 |
| **比赛** | 一个参赛者/参赛作品 | 100 entries in the competition |
| **物理空间** | 入口 | No entry = 禁止入内 |

## 6. Go up to / Go down to

### 原句
> The iterations only go up to 26M4W5

### 核心对比

想象一个数轴或楼梯：从低处**往上走（go up）**，走**到（to）**某个点就停了。

| 短语 | 方向 | 含义 |
|------|------|------|
| **go up to** | ↑ 往上 | 最高到…… |
| **go down to** | ↓ 往下 | 最低到…… |

```
26M4W5  ← go up to 这里就没了
26M4W4
26M4W3
26M4W2  ← 你当前在这
26M4W1
  ...

$500  ← Prices go up to $500（最高到500）
 $10  ← Prices go down to $10（最低到10）
```

### go down 单独用

| 用法 | 含义 | 例句 |
|------|------|------|
| 价格/温度 go down | 下降 | The price went down. |
| 服务器 go down | 宕机/挂了 | The server went down at 3am. |
| 太阳 go down | 落山 | The sun goes down at 7pm. |

## 7. From scratch

### 词源
**Scratch** 的原意是**刮出的一条线**（起跑线）。在早期赛跑中，起跑线就是在地上刮一道痕。所有人都从这条线开始跑——什么优势都没有，从零起步。

```
scratch line（起跑线）
    |
    ↓
    |-------- 跑 -------→ 终点
    从零开始，没有任何领先
```

### 核心含义
**from scratch = 从起跑线开始 = 从零开始，没有任何现成的东西可用**

### 对比 bootstrap

| 词 | 侧重点 |
|---|--------|
| **from scratch** | 强调**起点是零**，什么都没有 |
| **bootstrap** | 强调**自我启动的过程**，靠自己跑起来 |

两者经常一起出现：
> Bootstrap a project from scratch = 从零开始自行搭建一个项目

### 常见用法

| 例句 | 意思 |
|------|------|
| build from scratch | 从零搭建 |
| start from scratch | 推倒重来 |
| write it from scratch | 从头写，不抄不借 |
| cook from scratch | 用原材料自己做（不用预制菜/半成品） |

## 8. Sandbox 与浏览器安全

### 原句
> Blocked form submission to 'embed.aspx?src=...' because the form's frame is sandboxed and the 'allow-forms' [permission is not set]

### 关键词

**sandbox**（沙箱）：原意是小孩玩的沙坑——一个隔离的安全区域，随便玩都不会影响外面。在浏览器里，给 iframe 加上 `sandbox` 属性 = 把它关进沙箱，默认什么都不让干。

```
iframe（sandbox 模式，什么都不许干）
  └── 里面有个 form
        └── 用户点了提交
              └── 浏览器：❌ 不行，你在沙箱里，没给你 allow-forms 权限
```

```html
<!-- 沙箱模式：默认全部限制 -->
<iframe sandbox src="embed.aspx?src=..."></iframe>

<!-- 需要手动"开门"放行 -->
<iframe sandbox="allow-forms allow-scripts" src="embed.aspx?src=..."></iframe>
```

**submission**：submit（提交）+ -ion（名词后缀）= 表单提交

### 翻译
阻止了向 'embed.aspx?src=...' 的表单提交，因为表单所在的 iframe 处于沙箱模式，且没有开启 'allow-forms' 权限。

## 9. 一段关于 AI 安全注入的分析

### 原句 1
> Every file I opened had a `<system-reminder>` injected at the end instructing me to treat the code as potential malware.

### 断句
```
主句：
Every file [I opened]          → 我打开的每个文件
had                            → 都有
a <system-reminder>            → 一个 <system-reminder>
injected at the end            → 被注入在末尾

现在分词短语：
instructing me                 → 指示我
to treat the code              → 把代码当作
as potential malware           → 潜在的恶意软件
```

### 关键词

| 词 | 含义 |
|----|------|
| **injected** | 注入的（inject = in 进入 + ject 扔 = 扔进去） |
| **instructing** | 指示、命令（in- 向内 + struct 建造 = 在脑子里"建构"命令） |
| **treat...as** | 把……当作…… |
| **potential** | 潜在的（potent 有力量的 + -ial = 有可能发挥出来的） |
| **malware** | 恶意软件（mal- 坏的 + ware 软件） |

### 原句 2
> proceeding with the review you asked for.

**proceed** = pro-（向前）+ ceed（走）= 继续进行

翻译：继续进行你要求的那个代码评审。

### 原句 3
> Flagging it so you know the tool-result channel is pushing that content.

**flag** 作动词 = 标记出来、提请注意（原意：插一面旗引起注意）

**tool-result channel** = 工具返回结果的通道

```
用户直接说的话        →  user channel      → AI
工具返回的结果        →  tool-result channel → AI   ← 这里被注入了私货
系统提示词           →  system channel     → AI
```

翻译：提醒你一下，是工具返回结果的那个通道在推送那些（恶意注入的）内容。

### 原句 4
> Every time I called the Read tool on a file in your project, the tool result ended with an appended block like this (exact text, repeated at the bottom of each of the 4 genomics files I read):

**appended** = 附加的（append = ap- 朝向 + pend 挂 = 挂上去、追加到末尾）

翻译：每次我用 Read 工具读你项目里的文件，返回结果的末尾都会跟着一段被附加上去的内容。这段文字一字不差地重复出现在我读的那 4 个基因组学文件的底部。

| **con**cede | con- 完全 | 完全走开/让出 | 让步、承认 |

## 11. Settling utility bills

### 关键词

**settle**：原意"使安定下来、落定"（尘埃落定）。引申到钱的语境：把欠的账结清 → 尘埃落定，两不相欠。

核心直觉：**让某个"悬着"的事情落地、了结**。账单悬着 → settle → 付清了 → 落定。

| 用法 | 意思 |
|------|------|
| settle a bill | 结账、付清 |
| settle a debt | 还清债务 |
| settle a dispute | 解决争端 |
| settle down | 安顿下来 |

**utility**：util-（= use 使用）+ -ity（名词后缀）= 有用性 → 基础公共服务设施

| Utility | 中文 |
|---------|------|
| electricity | 电 |
| water | 水 |
| gas | 燃气 |
| sewage | 排污 |

**settling utility bills** = 缴清水电燃气费


## 13. 21st 的英语写法

**twenty-first**

### 两位数序数词规则
只需要把**最后一个词**变成序数词，前面不变：

| 数字 | 写法 | 规则 |
|------|------|------|
| 21st | twenty-**first** | twenty 不变，one → first |
| 32nd | thirty-**second** | thirty 不变，two → second |
| 43rd | forty-**third** | forty 不变，three → third |
| 55th | fifty-**fifth** | fifty 不变，five → fifth |
| 99th | ninety-**ninth** | ninety 不变，nine → ninth |

## 14. Cutting-edge / State-of-the-art / Bleeding-edge

### Cutting edge
**cutting edge** = 刀的刃口（切东西时最前面、最锋利的那条边）

- **edge** = 边缘、边（刀的边 = 刃）
- **cutting** = 用来切割的（修饰 edge）

引申：**最前沿、最先进的**

### State-of-the-art
- **state** = 状态、水平
- **of the art** = 这门技艺/领域的（art 这里是"技艺"的古义，和 artificial、artisan 同源）

**state of the art = 这门技艺当前的最高水平**

### Bleeding-edge
刀刃（cutting edge）往前切 → 切得太猛太深 → 出血了（bleeding）

```
稳定区域        cutting-edge（刀刃，在切）     bleeding-edge（切到出血了）
━━━━━━━━━━━━━━━━━━|━━━━━━━━━━━━━━━━━━━━━━━━|━━━━━━━━━━━━━━━
  成熟稳定             前沿但基本可靠              太新了，会受伤
```

暗示：太新了，可能有 bug、文档不全、随时被废弃、不兼容。

### 三者对比

```
安全区域 ←————————————————————→ 激进
state-of-the-art    cutting-edge    bleeding-edge
  当前最佳水平         最前沿          前沿到冒险
```

想象一把刀：

| 阶段 | 词 | 状态 |
|------|-----|------|
| 刀身 | state-of-the-art | 打磨完美、稳定可靠的部分 |
| 刀刃 | cutting-edge | 正在切入新领域的最前线 |
| 切到出血 | bleeding-edge | 切得太深，有风险有代价 |

| 词 | 视角 |
|----|------|
| **cutting-edge** | 正在**切开边界**，往外突破 |
| **state-of-the-art** | 在**现有边界内**已经到顶了 |
| **bleeding-edge** | 比 cutting-edge 还激进，新到**可能不稳定、有风险** |

## 16. Rise up

## 17. Scaffold

### 词源直觉
**Scaffold** 原意是**脚手架**——建筑工地上那种临时搭建的框架结构，工人站在上面盖房子。

```
  |---|---|---|
  |   |   |   |   ← 脚手架（scaffold）
  |---|---|---|
  |   |   |   |   ← 不是最终建筑，但让你能开始干活
  |---|---|---|
  ==================
      地面
```

### 在编程里
**scaffold = 自动生成一套基础代码骨架/模板，让你能快速开始开发**

就像脚手架让工人能站上去干活一样，代码 scaffold 让你不用从零写起，直接在生成的骨架上填充业务逻辑。

### 常见用法

| 例句 | 意思 |
|------|------|
| scaffold a new project | 自动生成一个新项目的骨架 |
| scaffold a component | 自动生成一个组件的模板文件 |
| Rails scaffold | Rails 框架自动生成 CRUD 代码 |
| scaffolding tool | 脚手架工具（如 Yeoman、create-react-app） |

核心直觉：**scaffold = 帮你把"架子"搭好，你只管往里填内容**

## 18. Stack

### 词源直觉
**Stack** 原意就是**一摞/一堆叠起来的东西**。

```
  ┌─────────┐
  │  盘子 4  │  ← 最后放上去的，最先拿走
  ├─────────┤
  │  盘子 3  │
  ├─────────┤
  │  盘子 2  │
  ├─────────┤
  │  盘子 1  │  ← 最先放的，压在最底下
  └─────────┘
```

### 不同语境

| 语境 | 含义 | 例子 |
|------|------|------|
| **数据结构** | 栈（后进先出 LIFO） | call stack = 调用栈 |
| **技术栈** | 一整套技术组合（一层叠一层） | tech stack = 技术栈 |
| **网络协议** | 协议栈 | TCP/IP stack |
| **full-stack** | 全栈（从底到顶都会） | full-stack developer |
| **日常** | 一摞、一堆 | a stack of books = 一摞书 |

### Tech stack 为什么叫 "栈"

```
┌──────────────────┐
│    React (前端)    │  ← 最上层，用户能看到
├──────────────────┤
│    Node.js (后端)  │
├──────────────────┤
│    MongoDB (数据库) │
├──────────────────┤
│    Linux (操作系统)  │  ← 最底层
└──────────────────┘

这一整摞 = your tech stack
```

**Full-stack developer** = 从最底层到最顶层这一摞全都能干的人。

### 动词用法

| 例句 | 意思 |
|------|------|
| Stack the chairs | 把椅子叠起来 |
| Errors are stacking up | 错误越堆越多 |
| Stack overflow | 栈溢出（叠太多，溢出来了） |

## 19. readinessProbe / Probe

### 拆解
- **readiness** = ready（准备好的）+ -ness（名词后缀）= **就绪状态**
- **probe** = **探针、探测器**（伸进去探测/检查）

**readinessProbe = 就绪探针 = 用来探测"你准备好了没"的东西**

### 形象理解

想象一个护士拿着体温计（probe）反复来量你的体温，确认你 OK 了才放你出院：

```
Kubernetes（护士）
    |
    ↓  反复探测
  ┌──────────┐
  │ 你的容器  │  ← "你好了没？能接客了吗？"
  └──────────┘
    |
    ├── 没好 → 不给你分配流量
    └── 好了 → OK，开始接收请求
```

### Kubernetes 三兄弟探针

| 探针 | 问的问题 | 没通过的后果 |
|------|---------|------------|
| **readinessProbe** | 你**准备好接活**了吗？ | 不给你分配流量（但不杀你） |
| **livenessProbe** | 你还**活着**吗？ | 杀掉重启 |
| **startupProbe** | 你**启动完成**了吗？ | 启动期间不做其他检查 |

### Probe 的其他语境

| 语境 | 含义 |
|------|------|
| 医学 | 探针（伸进去检查身体） |
| 航天 | 探测器（space probe = 太空探测器） |
| 调查 | 深入调查（probe into the case = 深入调查此案） |

核心画面：**伸一个东西进去，看看里面情况怎样**。

## 25. Overcommit

### 拆解
- **over-** = 超过、过度
- **commit** = 承诺、分配

**overcommit = 过度承诺/超量分配**

### 形象理解

```
一台机器实际内存：16GB

Pod A 说：我要 8GB    ┐
Pod B 说：我要 8GB    ├── 加起来承诺了 24GB
Pod C 说：我要 8GB    ┘

实际只有 16GB，却承诺出去 24GB → Overcommit！
```

就像航空公司**超卖机票**：飞机 200 个座位，卖了 220 张票——赌的是不会所有人都来。

### KubeMemoryOvercommit
**Kube + Memory + Overcommit** = Kubernetes 集群的内存超量分配告警

所有 Pod 声称要用的内存总量已经超过了节点实际拥有的内存。如果大家真的都用满了 → OOM Kill（杀进程）。

## mean → meant

### 变化
mean /miːn/ → meant /ment/ → meant（不规则，类似 deal → dealt, feel → felt）

### 多重含义

| 词性 | 含义 | 例句 |
|------|------|------|
| 动词 | 意思是 | What does this mean? |
| 动词 | 打算 | I meant to call you.（我本来打算给你打电话的） |
| 形容词 | 吝啬的/刻薄的（英式） | He's too mean to buy lunch. |
| 形容词 | 平均的（数学） | the mean value（平均值） |

### mean vs meaning vs meant

三者其实是同一个动作在**过程轴**上的三个不同位置：

```
   [打算/意图] ──► ★ mean（此刻在表达） ──► [被理解的内容]
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
      meant        meaning         （结果）
   （过去/完成）   （-ing 名词化）
   动作冻结在过去   动作凝固成"东西"
```

| 词 | 词性 | 在过程轴上的位置 | 例句 |
|---|---|---|---|
| **mean** | 动词（现在） | ★ 此刻正在"意指"这个动作 | What does this word **mean**? |
| **meant** | 动词（过去/过去分词） | 这个"意指"已经发生/已被定下 | I **meant** to call you.（我当时就打算……） |
| **meaning** | 名词 | 把"意指"动作冻成一个东西 | What's the **meaning** of this word? |

### meant 的本质：动作被"冻在过去"产生的两层引申

mean 的核心是「内心已经定好 → 表达出来」。一旦推到过去式 `meant`，"已经定好"这一面被放大，于是产生了两个常见用法：

1. **本来打算（过去的意图）**
   - I **meant** to call you, but I forgot.（我当时是打算打的）
   - 逻辑：意图在过去已经成立，但动作没完成 → 中文的"本来"

2. **be meant to = 被赋予某种意图 → 注定 / 应该**（被动 + 过去分词）
   - It was **meant** to be.（这是注定的 = 被某种力量"打算好"了）
   - This button is **meant** to be pressed.（这个按钮就是用来按的）
   - What is that **meant** to mean?（那是什么意思？= 那被设计来表达什么？）
   - 逻辑：被动语态把"谁打算"隐去，只剩"它被打算成这样" → 注定/本应

> 🔑 一句话总结：
> - **mean** = 此刻在意指
> - **meant** = 那个意指已经在过去定下了（→ 本来打算 / 注定）
> - **meaning** = 那个意指被装进名词里（→ 意思这个东西）

meaning 还能当形容词（少见）：a meaning look = 意味深长的眼神

## 比较级错误：more and more worse ❌ → worse and worse ✓

### 错误根因
把两套比较级系统混在一起了：

| 系统 | 规则 | "越来越…"的说法 |
|------|------|----------------|
| 规则变化（长词） | more + 原形 | more and more difficult |
| 不规则变化 | 词本身变形 | worse and worse |

**worse 本身已经 = more bad**，所以 "more worse" 就像说"更更坏"，重复了。

### 防错法则

> **已经变了形的比较级，前面绝不加 more。**

判断方法：这个词**长得还像原来那个词吗？**
- worse ≠ bad（变形了）→ 不加 more → worse and worse
- better ≠ good（变形了）→ 不加 more → better and better
- more difficult ≈ difficult（没变形）→ 用 more and more difficult

### 常见不规则比较级

| 原形 | 比较级 | "越来越…" |
|------|--------|----------|
| bad | worse | worse and worse |
| good | better | better and better |
| far | further | further and further |
| little | less | less and less |

## old vs elderly

### 核心区别：语气与尊重程度

| 词 | 词性 | 语气 | 适用场景 |
|---|---|---|---|
| **old** | adj. | 中性/直白，有时显得不礼貌 | 日常口语、描述物品、客观陈述 |
| **elderly** | adj.（也可名词化：the elderly） | 委婉、尊重、正式 | 正式写作、新闻、社会议题、雅思 |

### 为什么存在 elderly？

**old** 本身只是"年纪大的"，但在描述人时，直接说 "old people" 可能暗示"衰老、无用"，带有负面联想。

**elderly** = 一种 **委婉语（euphemism）**，专门用来礼貌地指代老年人，避免冒犯。

类似中文里"老人" vs "长者/老年人"的区别。

### 用法对比

| 表达 | 语气 | 例句 |
|---|---|---|
| old people | 直白，略显不敬 | Old people often feel lonely. |
| elderly people | 礼貌、正式 | Elderly people deserve more social support. |
| the elderly | 名词化，指整个群体 | The elderly are vulnerable to scams. |
| older people | 比较级，最中性 | Older people tend to sleep less. |

### 雅思写作建议

- 优先用 **elderly people** 或 **the elderly**（正式、得体）
- **older people** 也很好（中性，无冒犯）
- 避免 **old people**（考官可能觉得语言不够 sophisticated）

### elder vs elderly

| 词 | 词性 | 含义 |
|---|---|---|
| **elder** | 形容词/名词 | 年长的（仅用于家庭成员比较）；长辈 |
| **elderly** | 形容词 | 年迈的（用于描述老年人） |

- my **elder** brother = 我哥（比较关系）
- an **elderly** man = 一位老年人（描述年龄段）

### 词源逻辑

- old → elder（比较级变体）→ elderly（elder + `-ly` 形容词后缀 = "具有长者特征的"）
- `-ly` 在这里不是副词后缀，而是形容词后缀（类似 friendly, lovely, lonely）

## found：两个完全不同的词

### 关键认知

**found 不是一个词，而是两个长得一模一样的词（同形异源词）。**

| # | 原形 | 词性 | 含义 | 过去式 | 来源 |
|---|---|---|---|---|---|
| 1 | **find** | v. | 发现、找到 | found | 古英语 findan |
| 2 | **found** | v. | 创立、建立 | founded | 拉丁语 fundare（打地基） |

### 为什么长一样？

这是**纯巧合**。两个词来自完全不同的语言：

- **find → found**：古英语不规则动词变位（类似 bind → bound）
- **found（创立）**：来自拉丁语 fundus（底部、基础）→ fundare（奠基）→ 法语 fonder → 英语 found

它们只是碰巧在英语中拼写相同，没有任何语义关联。

### 如何区分？

**看过去式：**

| 原形 | 过去式 | 过去分词 |
|---|---|---|
| find（发现） | found | found |
| found（创立） | **founded** | **founded** |

所以：
- "The company was **founded** in 1998." → 创立（规则变化 -ed）
- "I **found** my keys." → 发现（find 的过去式）

### 相关词族

found（创立）→ founder（创始人）→ foundation（基础/基金会）

这个词族都和"打地基、建立根基"有关：
- foundation = 地基（建筑）/ 基础（抽象）/ 基金会（为某事业奠基）
- founder = 奠基人 = 创始人

### found vs fund：易混淆区分

两者同源（都来自拉丁语 fundus = 底部/基础），但在英语中已经分化成不同的词：

| 词 | 词性 | 含义 | 核心意象 |
|---|---|---|---|
| **found** | 动词 | 创立、建立 | 打地基 → 从无到有建起来 |
| **fund** | 名词/动词 | 基金 / 资助 | 底部的储备 → 一笔钱作为基础支撑 |

语义分化逻辑：

```
拉丁语 fundus（底部、基础）
├── fundare（奠基）→ 英语 found（创立）→ founder / foundation
└── fundus（底部储备）→ 英语 fund（资金）→ funding / fundraise
```

- **found** 强调"动作"：把地基打下去 → 创立一个组织/公司
- **fund** 强调"资源"：底下垫着的那笔钱 → 基金、资金

快速判断：
- "谁 founded 了这家公司？" → 创立（动作）
- "这家公司需要更多 funding" → 资金（资源）
- "a Tier-1 fund" → 一个顶级基金（一笔钱/一个机构）

## choose vs choice

### 核心关系

| 词 | 词性 | 含义 | 发音 |
|---|---|---|---|
| **choose** | v. | 选择（动作） | /tʃuːz/ |
| **choice** | n. | 选择（结果/选项） | /tʃɔɪs/ |

动词 → 名词，但**不是**加后缀变的，而是词源上的同族异形词。

### 词源逻辑

两者都来自古英语 cēosan（选择）：
- 动词形式 → choose
- 名词形式 → choice（经由古法语 chois 影响了拼写）

所以它们不是 choose + 后缀 = choice，而是**同一个词根在不同词性上的不同演化形态**。

### choose 的变位

| 原形 | 过去式 | 过去分词 |
|---|---|---|
| choose /tʃuːz/ | **chose** /tʃoʊz/ | **chosen** /ˈtʃoʊzən/ |

不规则变化，元音交替（类似 freeze → froze → frozen）。

### 用法对比

| 用法 | 例句 |
|---|---|
| choose（动词） | You can **choose** any color. |
| chose（过去式） | She **chose** the red one. |
| chosen（过去分词） | He was **chosen** as the leader. |
| choice（名词） | It's your **choice**.（这是你的选择） |
| choice（名词） | You have three **choices**.（你有三个选项） |

### choice 还能当形容词

choice 作形容词 = **上等的、精选的**（正式/书面）

> choice beef = 精选牛肉
> a choice selection of wines = 精选葡萄酒

逻辑：被"选出来的" → 精挑细选的 → 上等的

## Sophomore 与英语年级体系

### Sophomore 词源拆解

**Sophomore** = **sopho**（wise 智慧）+ **more**（fool 愚蠢）

这个词本身就藏着一个精妙的矛盾：**"自以为聪明的傻瓜"** — 形容大二学生学了一年，觉得自己什么都懂了，但其实还差得远。这就是为什么英语里有个形容词 **sophomoric**，意思是"幼稚的、肤浅的自以为是"。

### 四年制命名法

美国学校年级系统的核心逻辑：**一套四年制命名法被复用了两次**（高中用一次，大学再用一次）。

| 年级 | 名称 | 词源逻辑 |
|------|------|----------|
| 第1年 | **Freshman** | fresh（新鲜的）+ man → 新来的人 |
| 第2年 | **Sophomore** | sopho（智慧）+ more（愚蠢）→ 半瓶水晃荡 |
| 第3年 | **Junior** | 拉丁语 junior = 较年轻的 → 还没到头 |
| 第4年 | **Senior** | 拉丁语 senior = 较年长的 → 最资深的 |

### 高中和大学复用同一套

| 高中 (High School) | 大学 (College/University) |
|---|---|
| 9th grade → Freshman | Year 1 → Freshman |
| 10th grade → Sophomore | Year 2 → Sophomore |
| 11th grade → Junior | Year 3 → Junior |
| 12th grade → Senior | Year 4 → Senior |

所以当美国人说 "I'm a sophomore"，需要根据上下文判断是**高二**还是**大二**。

### 高中之前（K-8）直接用数字

| 阶段 | 年级 | 说法 |
|------|------|------|
| Elementary School（小学） | K-5 | Kindergarten, 1st–5th grade |
| Middle School（初中） | 6-8 | 6th, 7th, 8th grade |

### 背后的思维模型：社会角色递进

这套命名不是在描述"第几年"，而是在描述**你在群体中的社会地位和心理状态**：

```
Freshman  → 你是新人，一切都新鲜，你什么都不懂
Sophomore → 你学了一年，开始自以为是（但还是嫩）
Junior    → 你有经验了，但还不是最资深的
Senior    → 你是老大哥/老大姐，即将毕业离开
```

这就是为什么英语不说 "Year 1, Year 2"（英国才这么说），而用这四个有性格的词。

延伸到职场：**Senior engineer** vs **Junior engineer** — 不是说年龄，是说资历和能力层级。
