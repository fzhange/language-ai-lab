# Pasted-text collections: design

## Purpose and scope

People encounter useful language-learning text outside pages supported by the highlighting extension. Provide a dedicated place in `language-learning-web` where a signed-in user can paste text, color selected words, and create, read, update, and delete saved items. The first release is collection and CRUD only: no files, URLs, source attribution, extension changes, or AI tutor integration. Preserve a plain-text representation so later tutor integration can read the content without interpreting presentation markup.

## Approach

Use Tiptap's React editor with only plain text/paragraphs and inline foreground-color and highlight-background marks. Quill also supports color/background but Tiptap's composable extensions fit a narrowly scoped editor; a custom contenteditable editor would make selection, paste, and editing fragile. Offer a small fixed accessible palette and a clear-formatting action. Paste external material as plain text; do not retain its HTML, scripts, images, links, or other rich formatting. Preserve line breaks. The user can apply colors to selected spans or type with an active color. Avoid arbitrary CSS values and HTML serialization.

## Database and authorization

Create a new `public.whw_collections` table in the existing Supabase project, separate from `whw_highlights` and from the read-only knowledge-base notes. Columns: `id UUID` primary key (generated by database), `user_id UUID NOT NULL` referencing `auth.users(id)`, `content_text TEXT NOT NULL` (non-whitespace content), `content_doc JSONB NOT NULL` (Tiptap document with the colored spans), and `created_at`/`updated_at TIMESTAMPTZ NOT NULL` with database defaults and an update trigger. Index `(user_id, created_at DESC, id DESC)` for stable newest-first retrieval. Delete removes the row after confirmation (no extension-style tombstone or offline sync).

Enable RLS. Grant CRUD to authenticated clients with SELECT and DELETE `USING (auth.uid() = user_id)`, INSERT `WITH CHECK (auth.uid() = user_id)`, and UPDATE both `USING` and `WITH CHECK` on that condition. Anonymous clients have no access; client-provided IDs/owner fields alone confer no privileges. Include migration SQL in the web repository; do not silently assume this table exists. Deploy/apply the migration to the target Supabase project only after verifying the connected project and schema; if no connection/permission is available, report that deployment step as outstanding.

On save, derive `content_text` from the editor's document and submit both fields in one insert/update; on load, validate the expected limited document structure and allowlisted color values before rendering. Treat database content as untrusted even with RLS, because a client can send invalid document JSON. Render structured text with safe React/Tiptap nodes, not `dangerouslySetInnerHTML`. A corrupt entry must not compromise the list or editor; show an error for that item instead. Do not attempt frontend workarounds for server-side schema, permission, or data errors.

## User flow and UI

Add `/collections` and a "My Collections" navigation entry without changing `/notes` or `/highlights`. Show items newest first, in a responsive list with enough preview text and timestamps to identify them; load in pages rather than fetching an unbounded table. An add action opens the editor with empty content; edit loads existing content and formatting. A small formatting toolbar supports foreground color, background highlight, and clear formatting for the current selection. Show disabled save for empty/whitespace-only text, pending states that prevent duplicate submissions, loading and empty states, and a confirm step before delete. After successful mutations refresh/update the list; on failure retain the unsaved editor state and show an actionable error. If Supabase is not configured or the user is not signed in, show the same kind of unavailable/sign-in state as the highlights page.

## Validation and acceptance

- A signed-in user can save pasted text, reload the page, and see selected-word foreground and background colors unchanged alongside the readable plain-text field.
- Editing preserves existing formatting; clearing a selection's formatting affects only the selection; creating/updating blank content is rejected.
- Deleting requires confirmation and removes only the selected item; canceled deletion changes nothing.
- A second user cannot list, read, edit, or delete the first user's items (verify RLS, not just UI filters).
- Pasted HTML/script content is treated as text, unsupported or malformed stored formatting cannot execute code, and application errors do not discard unsaved edits.
- Existing highlights, knowledge-base notes, and tutor behavior remain unchanged. Run targeted UI/unit tests plus build and lint; verify database policies with two authenticated identities when a test database is available.
